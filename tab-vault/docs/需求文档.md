# 标签组备份扩展 开发需求文档

> **目标读者**：负责编码的 AI / 开发者。本文档是唯一需求来源，按此实现即可，无需另行设计。
> **产品名（暂定）**：标签保险箱（TabVault）
> **日期**：2026-09-10 · **版本**：v1.0
> **平台**：Chrome / Catsxp 及任意 Chromium 内核浏览器（Manifest V3）

---

## 1. 一句话定位

把当前窗口的标签页（含标签分组结构）保存为可命名的快照，随时按原分组结构一键恢复，并支持导出/导入 JSON 文件实现跨设备迁移。**防丢失是核心诉求。**

## 2. 功能需求（按用户确认的决策）

### F1 保存快照
- 保存**当前窗口**的全部标签页（多窗口支持明确**不做**，见 N1）。
- 标签分组（tab groups）必须原样保存：**组名、颜色、折叠状态、组内标签顺序**。
- 散标签（不属于任何分组的）：**默认保存**，归入一个虚拟组"未分组"（unnamed group，不设组名不设颜色）。**可在设置中关闭**（关闭后散标签不保存，见 S2）。
- 固定标签（pinned）：**保留 pinned 状态**，恢复时原样钉住。
- 快照命名：**自动命名**，格式 `YYYY-MM-DD HH:mm`（本地时间），保存后可在列表中**重命名**。
- 保存动作完成后有轻量反馈（如按钮短暂变为"已保存 ✓"，不弹系统通知）。

### F2 快照管理
- 弹窗（popup）内列出全部快照：显示名称、保存时间、标签数、分组数。
- 每条快照支持：**恢复、重命名、删除**。
- 恢复行为：**叠加打开，绝不关闭或影响当前已开标签**（用户明确要求，宁重复不丢数据）。恢复完成后有反馈。
- 删除需二次确认（弹窗内确认即可，不用系统对话框）。

### F3 恢复规则（实现重点，务必精确）
1. 读取快照数据，按保存时的分组结构重建：
   - 每个分组：先 `chrome.tabs.create()` 创建该组第一个标签 → `chrome.tabs.group({tabIds})` 归组 → `chrome.tabGroups.update(groupId, {title, color, collapsed})` 还原组属性。
   - "未分组"的散标签直接 create，不归组。
   - pinned 标签：`chrome.tabs.create({pinned: true})`，且 pinned 标签必须排在窗口最前（Chrome 规则，按保存顺序排列）。
2. **组内标签顺序**与保存时一致（按顺序逐个 create 后统一 group，或分组后用 `chrome.tabs.move` 校正）。
3. 恢复自检：恢复完成后比对打开的标签数与快照标签数，不一致时在 UI 上提示"恢复 N/M 个标签"。

### F4 导出 / 导入（跨设备）
- **导出**：单条快照或全部快照 → JSON 文件（`chrome.downloads.download()`），文件名如 `tabvault-2026-09-10.json`。导出全部时是快照数组，单条时是对象。
- **导入**：选择 JSON 文件 → 校验结构（见 §5）→ 合并进现有列表（`id` 重新生成，不覆盖现有快照；重名快照允许并存，时间戳区分）。
- 导入成功后列表刷新并提示"导入 N 条"。

### F5 设置页（简版）
- S1：语言——**仅中文**，无需 i18n 框架（文案集中一个文件即可，方便未来扩展）。
- S2：**保存散标签开关**（默认开）。
- 设置页可以是 popup 里的一个折叠区，不必独立 options 页。

### F6 明确不做（本期范围外）
- ❌ 多窗口保存/还原
- ❌ 自动定时快照
- ❌ 云同步 / NAS 上传
- ❌ AI 整理、按域名自动分组
- ❌ 会话历史搜索
以上留作 v2+，实现时不要为它们预留过度架构，但**快照 JSON 结构要允许未来加字段**（见 §5）。

## 3. 技术要求

- Manifest V3；`permissions`: `tabs`, `tabGroups`, `downloads`, `storage`；不需要 `host_permissions`。
- 存储：`chrome.storage.local`（默认配额 10MB，足够数千条快照；保存失败要处理 `QUOTA_BYTES` 超限：提示用户删除旧快照）。
- 纯原生 HTML/CSS/JS（popup + 可选 options），**禁止引入任何框架/构建工具**——交付物是可直接"加载已解压的扩展程序"的文件夹。
- **界面全中文**，深色/浅色跟随系统（`prefers-color-scheme`），代码注释中文。
- 兼容 Chrome ≥ 116（`chrome.tabGroups` 稳定版即可，无需 beta API）。

## 4. UI 结构（popup，宽度约 360px）

```
┌─────────────────────────────┐
│ 标签保险箱        [⚙设置]   │
├─────────────────────────────┤
│ [💾 保存当前窗口]            │  ← 主按钮，最大最显眼
├─────────────────────────────┤
│ 快照列表（倒序，新的在上）    │
│ ┌─────────────────────────┐ │
│ │ 2026-09-10 10:26    12标签3组 │
│ │ [恢复] [重命名] [导出] [🗑] │ │
│ └─────────────────────────┘ │
│ …                           │
├─────────────────────────────┤
│ [📤 导出全部] [📥 导入]      │
└─────────────────────────────┘
```
- 重命名：行内编辑（点击名称变输入框，回车/失焦保存）。
- 空列表状态：显示"还没有快照，点击上方按钮保存当前窗口"。

## 5. 快照 JSON 结构（版本化，向后兼容）

```json
{
  "format": "tabvault",
  "version": 1,
  "exportedAt": "2026-09-10T10:26:00+08:00",
  "snapshots": [
    {
      "name": "2026-09-10 10:26",
      "createdAt": 1725936000000,
      "groups": [
        {
          "title": "工作",
          "color": "blue",
          "collapsed": false,
          "tabs": [
            {"url": "https://example.com", "title": "示例", "pinned": false},
            {"url": "https://b.com", "title": "B", "pinned": true}
          ]
        },
        {
          "unnamed": true,
          "tabs": [ { "url": "https://c.com", "title": "C", "pinned": false } ]
        }
      ]
    }
  ]
}
```
- `color` 取值限 Chrome 组颜色枚举：grey/blue/red/yellow/green/pink/purple/cyan/orange。
- 单条导出时 `snapshots` 数组只含一条（结构不变，导入逻辑统一处理数组）。
- 未来加字段只增不改名；导入时未知字段忽略。

## 6. 验收标准（逐条可测）

1. 开 3 个分组（不同名不同色，其一折叠）+ 2 个散标签 + 1 个 pinned 标签 → 保存 → 关闭全部 → 恢复：分组名/颜色/折叠态/组内顺序/pinned 全部一致，散标签仍为散标签。
2. 关闭"保存散标签"后再保存：快照中无散标签。
3. 恢复不影响任何已打开标签；恢复后弹出"已恢复 N 个标签"。
4. 导出全部 → 清空扩展数据（或换浏览器）→ 导入 → 列表与快照内容完整还原，可再次恢复。
5. 重命名、删除（含二次确认）、空列表文案均正常。
6. 快照 200 条时 popup 打开 < 1 秒、滚动流畅。
7. 在 Catsxp 最新版实际加载测试通过（用户将用"加载已解压的扩展程序"方式安装）。

## 7. 交付物

1. 扩展源码文件夹（manifest.json / popup.html / popup.css / popup.js / icons/16|48|128.png，图标可用占位）。
2. `README.md`：安装步骤（开发者模式加载）、使用说明、数据存放位置说明。
3. 快照 JSON 的 1 份示例文件。

## 8. 边界与异常处理清单

| 场景 | 期望行为 |
|---|---|
| 当前窗口只有 1 个空白新标签页 | 允许保存但提示"当前窗口没有可保存的内容" |
| `chrome://` 等系统页标签 | 保存时跳过（恢复时也无法由扩展创建），UI 说明"系统页未保存" |
| storage 写入失败/超限 | 明确报错文案，指引删除旧快照 |
| 导入文件非法/被篡改 | 拒绝并提示，不影响现有数据 |
| 恢复中部分 URL 创建失败 | 跳过并计入"恢复 N/M"，不中断整体 |
